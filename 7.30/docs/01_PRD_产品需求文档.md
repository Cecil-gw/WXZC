## 1. 项目背景与目标

### 1.1 业务背景

某保险公司拥有大量历史客户数据，希望利用这些数据完成两件事：

1. **预测哪些客户更可能购买车险**：传统粗放营销转化率低、成本高，需要用机器学习对客户购买概率排序，把有限营销资源投到高潜客户身上。
2. **生成个性化营销文案**：高潜客户确定后，人工写邮件效率低且千篇一律，希望用大模型（LLM）根据每个客户画像自动生成有温度、有针对性的营销邮件。

业务痛点：

- 客户数据分散在 Excel，缺乏统一管理入口；
- 营销人员不懂建模，需要把训练-评估-预测封装成"一键"操作；
- 数据严重不平衡（约 87% 客户不买、13% 购买），直接建模会偏向多数类，对真正会买的少数类识别能力差；
- 营销文案个性化不足，转化率低。

### 1.2 项目目标

构建一个 Web 系统，打通 **「数据 → 建模 → 预测 → 营销」** 闭环：

| 目标     | 衡量指标                         |
| ------ | ---------------------------- |
| 数据集中管理 | 支持 Excel 批量导入，提供数据概览与质量检查    |
| 自动化建模  | 一键训练多算法，按 ROC-AUC 自动选优，无需懂代码 |
| 概率预测   | 对全量客户预测投保概率，可按概率排序筛选高潜客户     |
| 智能营销   | 调用大模型为高潜客户生成个性化营销邮件          |
| 权限管控   | 区分管理员与普通用户，关键操作有审计日志         |

### 1.3 业务价值

- 营销 ROI 提升：把营销资源从"全量撒网"转向"top 10% 高潜客户"；
- 人力成本下降：邮件文案由 LLM 自动生成，营销人员只需审阅微调；
- 数据资产沉淀：客户数据、模型实验、营销记录全部入库可追溯。

## 2. 用户角色与权限（RBAC）

系统采用基于角色的访问控制（RBAC），共两类角色：

| 角色           | 角色定位            | 可用功能                     | 不可用功能              |
| ------------ | --------------- | ------------------------ | ------------------ |
| `admin`（管理员） | 系统管理者，负责数据建模全流程 | 全部功能                     | —                  |
| `user`（普通用户） | 业务运营者，使用模型结果做营销 | 数据查看、模型预测、邮件生成、Prompt 编辑 | 模型训练、模型导入导出、操作日志查看 |

> 角色在注册时由服务端硬编码为 `user`，普通用户无法自行升权为 `admin`，防止越权。

## 3. 功能需求

### 3.1 用户认证模块

| 功能点    | 说明                              | 角色  |
| ------ | ------------------------------- | --- |
| 登录     | 用户名密码校验通过后签发 JWT 令牌             | 全部  |
| 注册     | 注册新用户，密码 bcrypt 哈希存储，角色强制为 user | 全部  |
| 获取当前用户 | 凭 Token 获取当前登录用户信息              | 已登录 |
| 登出     | JWT 无状态，前端丢弃 Token 即登出          | 已登录 |

**安全要求**：

- 密码禁止明文存储，必须使用 bcrypt（带随机盐）哈希；
- 登录失败统一返回"用户名或密码错误"，防止用户名枚举撞库；
- Token 有效期默认 24 小时，可通过配置调整；
- 注册接口不接收 role 字段，防越权。

### 3.2 数据管理模块

| 功能点      | 说明                                  | 角色  |
| -------- | ----------------------------------- | --- |
| Excel 上传 | 接收 .xlsx 文件，解析后批量入库；上传覆盖旧数据         | 已登录 |
| 客户列表分页   | 多条件过滤（性别/年龄区间/是否已投保/ID 关键词）+ 分页     | 已登录 |
| 数据概览统计   | 总数、性别分布、Response 分布、年龄统计            | 已登录 |
| 数据质量报告   | 缺失值、重复值、字段类型统计                      | 已登录 |
| EDA 可视化  | 年龄分布、响应分布、保费分布、性别×响应交叉图（base64 PNG） | 已登录 |

**数据要求**：

- 支持 38 万行级批量导入，必须分批提交（每批 5000 条）防锁库；
- 字段命名与 保险交叉销售数据集对齐（Gender/Age/Driving_License/.../Response）。

### 3.3 模型训练模块

| 功能点   | 说明                                                    | 角色      |
| ----- | ----------------------------------------------------- | ------- |
| 训练多模型 | 一键训练 Logistic Regression / XGBoost / RandomForest 三算法 | 仅 admin |
| 自动选优  | 按 ROC-AUC 选最佳模型，标记 is_best                            | 仅 admin |
| 实验记录  | 每次训练的指标、参数、模型文件路径入库                                   | 已登录可查   |
| 评估可视化 | ROC 曲线、指标对比、混淆矩阵、特征重要性                                | 已登录     |
| 模型导出  | 下载 .joblib 模型文件                                       | 仅 admin |
| 模型导入  | 上传 .joblib 模型文件复用                                     | 仅 admin |

**算法要求（重点）**：

- 数据正负比约 13:87 严重不平衡，必须做不平衡处理：
  - LR / RandomForest：`class_weight="balanced"`
  - XGBoost：`scale_pos_weight = 负样本数 / 正样本数`
- 拆分训练/测试集必须 `stratify=y` 分层抽样；
- 标准化只能 `fit_transform` 在训练集，测试集 `transform`，防数据泄漏；
- 模型与 scaler 必须 `joblib.dump` 一起存盘，预测时复用同一 scaler。

### 3.4 概率预测模块

| 功能点    | 说明                                     | 角色  |
| ------ | -------------------------------------- | --- |
| 全量预测   | 加载最佳模型，对全部客户 `predict_proba` 取正类概率     | 已登录 |
| 概率回写   | 把预测概率回写到 `customers.predicted_prob` 字段 | 已登录 |
| 查看最佳模型 | 查询当前 is_best=True 的模型信息                | 已登录 |

**业务要求**：

- 用概率（`predict_proba`）而非硬标签（`predict`），因为营销场景需要按概率排序取 top N；
- 预测时必须用训练时的 scaler 做 `transform`，不能重新 `fit`。

### 3.5 营销邮件模块

| 功能点         | 说明                               | 角色  |
| ----------- | -------------------------------- | --- |
| 高潜客户筛选      | 按预测概率分位（默认 top 10%）筛选高潜客户        | 已登录 |
| LLM 生成邮件    | 为高潜客户调用大模型生成个性化营销邮件并存库           | 已登录 |
| 邮件记录列表      | 分页查询历史生成记录，可按 status 过滤          | 已登录 |
| 邮件详情        | 查看单封邮件完整正文                       | 已登录 |
| Prompt 模板管理 | 查询/更新当前生效的 Prompt 模板（运营改文案不用动代码） | 已登录 |

**AI 要求**：

- 使用 OpenAI 兼容协议调用大模型（默认 qwen-flash），换模型只改配置；
- Prompt 必须含：角色设定 + 客户画像（自然语言）+ 输出格式要求（严格 JSON）；
- 客户画像要把 ML 编码值（0/1）反解为自然语言（如"有驾照"/"曾受损"），LLM 才能理解；
- LLM 调用失败必须降级返回 `{success: False}`，不能拖垮整个业务流程。

### 3.6 操作日志模块

| 功能点    | 说明                              | 角色      |
| ------ | ------------------------------- | ------- |
| 操作日志查询 | 分页查询全量操作日志，可按 user_id/action 过滤 | 仅 admin |

**审计要求**：训练、预测、邮件生成、模型导入等关键操作必须记 `OperationLog`（user_id + action + details + 时间）。

### 3.7 前端管理后台

- 单页应用（SPA），hash 路由；
- 响应式布局，支持桌面浏览器；
- 登录表单 + 主界面容器；
- RBAC 菜单：admin 显示 11 个菜单项，普通用户显示 7 个；
- 所有请求自动携带 JWT，统一处理 `{code, message, data}` 响应。

## 5. 数据需求

### 5.1 数据集

采用保险交叉销售公开数据集（Health Insurance Cross Sell Prediction），字段如下：

| 字段                   | 含义       | 取值                              |
| -------------------- | -------- | ------------------------------- |
| id                   | 客户 ID    | 整数                              |
| Gender               | 性别       | Male / Female                   |
| Age                  | 年龄       | 20~85                           |
| Driving_License      | 是否有驾照    | 0 / 1                           |
| Region_Code          | 地区编码     | 浮点                              |
| Previously_Insured   | 是否已有车险   | 0 / 1                           |
| Vehicle_Age          | 车龄       | < 1 Year / 1-2 Year / > 2 Years |
| Vehicle_Damage       | 车辆是否曾受损  | Yes / No                        |
| Annual_Premium       | 年缴保费     | 浮点                              |
| Policy_Sales_Channel | 销售渠道编码   | 浮点                              |
| Vintage              | 客户保有天数   | 整数                              |
| Response             | 是否购买（标签） | 0 / 1（正负比约 13:87）               |

### 5.2 数据流

```
Excel 文件 → pandas 解析 → 字段映射 → 批量入库(customers)
                                      ↓
                          特征编码 → 标准化 → 分层拆分
                                      ↓
                          三算法训练 → 评估 → 选优 → 持久化(.joblib)
                                      ↓
                          加载最佳模型 → predict_proba → 回写概率
                                      ↓
                          按概率分位筛选高潜 → LLM 生成邮件 → 入库
```

## 6. 接口需求概述

所有接口统一返回 `{ code, message, data }`，`code=0` 成功。需鉴权接口在 Header 携带 `Authorization: Bearer <token>`。

| 模块  | 前缀              | 主要端点                                                                   |
| --- | --------------- | ---------------------------------------------------------------------- |
| 认证  | `/api/v1/auth`  | login / register / me / logout                                         |
| 数据  | `/api/v1/data`  | upload / customers / statistics / quality / visualization              |
| 模型  | `/api/v1/model` | train / experiments / best / predict / visualization / export / import |
| 邮件  | `/api/v1/email` | targets / generate / prompt / records                                  |
| 日志  | `/api/v1/logs`  | 操作日志查询（仅 admin）                                                        |

> 详细接口契约见 `03_API接口文档.md`。

## 8. 验收标准

1. admin/admin123 首次启动自动创建，可正常登录拿到 JWT；
2. 上传 Excel 后 `customers` 表有数据，统计/质量/可视化接口正常返回；
3. 训练三算法后 `experiments` 表有 3 条记录，且 `is_best` 唯一为真；
4. 全量预测后 `customers.predicted_prob` 不为空；
5. 高潜筛选返回 top 10% 客户，LLM 生成邮件入库（已配 API Key 时 status=generated）；
6. 普通用户访问 `/model/train`、`/logs` 返回 403；
7. 未带 Token 访问受保护接口返回 401；
8. 前端 SPA 可完成登录→上传→训练→预测→生成邮件全流程。
